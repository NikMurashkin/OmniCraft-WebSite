Modules Marketplace: Specialized Extensions Ecosystem ​

The daily craft of an artisan, service technician, or bespoke studio owner is far too nuanced to force into a single, cluttered monolith screen. A specialized tool essential to a leatherworker (such as surface area estimation or stitch pricking calculators) is useless overhead to a watchmaker or electronics technician, unnecessarily crowding the interface and slowing workflow execution.

To resolve this challenge, OmniCraft ERP employs a modular architecture featuring cross-cutting modules and an integrated extensions catalog (Marketplace):

  • Lightweight Core Engine: the foundation of the platform contains strictly universal business modules (assets, inventory, cash flow, balance sheet, retail sales, and online storefront);
  • Tailored Specialization: craftsmen independently choose and activate niche industry extensions designed specifically for their trade;
  • Cross-Cutting Availability: unlike workshop stockrooms or recipes bound to a single business, active extensions operate globally across all workspaces and preserve their records through organizational changes.

Marketplace Architecture: How the Catalog Operates ​

Access the catalog with a single click: select "Modules Marketplace" from the right side navigation panel or the application drawer.

The program displays a modular dialog window populated with available extensions, fetching the active catalog structure via a secure communications channel:

Fault Tolerance and Offline Stability ​

OmniCraft ERP is built on an uncompromising local-first design principle: network hiccups never halt the master's workflow:

  • In-Memory Catalog Caching: a fetched catalog is safely cached in application RAM. If internet connectivity drops, the system renders the cached directory instantly without freezing;
  • Helpful Network Recovery Screen: if connection timeouts occur on a fresh cold launch, the dialog displays an informative notification with a network status badge and a "Retry" button.

Step-by-Step Guide: Connecting a Free Module ​

  • Step 1: Open the Marketplace. Click "Modules Marketplace" in the side navigation panel or application drawer.
  • Step 2: Select Your Tool. Locate the module card (such as "Ambassador") and click the emerald "Connect Free" button.
  • Step 3: Instant Readiness. The system verifies the cryptographic license token and mounts the new module into your sidebar menu. No application restart or external downloads required.

Purchasing Commercial Trade Modules ​

OmniCraft ERP rejects predatory recurring microtransactions. Commercial modules are acquired on a one-time, perpetual basis:

  1. Click "Buy for $X" on your chosen trade extension card;
  2. Your default web browser opens the verified checkout portal;
  3. Complete the payment via credit card, wire transfer, or instant payment methods;
  4. The billing server binds the module ID to your personal license key. Upon returning to OmniCraft ERP, the module transitions to "Installed".

Fair Economics for Craftsmen

You never pay for features you do not use. A carpentry shop invests in sheet nesting, an apparel brand in sizing charts, and a hardware repair center in vendor parts catalogs. The core ERP remains lean and completely free of artificial bloat.

Engineering Standards: Monolithic Security and Lazy Loading ​

Most software systems offering add-on marketplaces suffer from two chronic architectural flaws: malware vulnerabilities when downloading unverified external code, and performance degradation caused by memory leaks.

OmniCraft ERP eliminates these risks at the binary compilation layer:

  • Core ERP Framework:
    Assets, Warehouse, Cash, Balance — compiled directly into the binary and immediately operational.
  • Built-In "Ambassador" Module:
    Compiled within the monolithic executable; loaded into RAM strictly when the tab is accessed (0 MB idle).
  • Future Industry Extensions:
    Isolated architectural capsules lazily initialized on demand without external file downloads.

1. In-Tree Monolithic Compilation ​

All official extensions within the OmniCraft ERP ecosystem are compiled directly into the monolithic binary executable using industrial C-level translation.

  • No Dynamic File Downloads: Clicking "Connect" never downloads dynamic libraries (.dll) or raw scripts (.py) from external web servers. The code is already present, encrypted, and cryptographically verified within the binary;
  • 100% Protection Against Vulnerabilities: Third-party remote code execution (RCE) vectors through plugin tampering are architecturally impossible;
  • Zero Antivirus Conflicts: Windows Defender and enterprise endpoint scanners never generate false-positive alerts, as file disk structures remain unmodified.

2. Lazy Loading: Zero Idle Memory Overhead ​

Every module operates as an isolated architectural capsule.

Until the craftsman clicks the module tab in the side menu, its interface elements, event handlers, and SQLite query bridges are never initialized in computer RAM. Having five or twenty modules active inside the binary does not add a single millisecond to application boot times.

Engineering Note: How Lazy Loading Preserves Performance

During startup, OmniCraft ERP parses only lightweight declarative module manifests (IDs, titles, and icons). Database migrations and UI controls instantiate strictly on-demand upon first user interaction.

Data Isolation: Global Extensions vs. Local Workspaces ​

The OmniCraft ERP modular engine strictly separates data boundaries:

Database FileScope LayerStored Domain Data
global_extensions.dbGlobal LayerMarketing, referral linkages, campaigns, and cross-workspace attribution.
workspace.dbLocal WorkspaceWarehouse stocks, machinery, cash flow, and client orders of a specific shop.
  • Cross-Cutting Global Modules: Extensions like "Ambassador" maintain their schema inside a dedicated database: global_extensions.db. They operate above individual workshops.
  • Immunity to Workspace Resets: If you reset, archive, or purge a specific craft workspace, global modules retain 100% of their records. Referral networks, campaign histories, and marketing links remain intact.
  • Workspace-Bound Extensions: Modules dealing directly with shop-floor operations (material nesting, bespoke service jobs) write tables into the active workspace database using the mod_* prefix.

Partnership Continuity Across Businesses

You can run a leather goods atelier, simultaneously manage a tool sharpening shop, and close an underperforming retail project. The "Ambassador" module continues tracking commissions and partner traffic seamlessly regardless of business closures.

Frequently Asked Questions ​

Is an active internet connection required to use an installed module? ​

No. An internet connection is required for only a few seconds during initial activation or purchase to verify the cryptographic license signature. All routine operations (creating campaigns, generating links, running calculations) execute 100% locally and offline.

What happens to activated modules when migrating to a new computer? ​

All module authorizations are cryptographically anchored to your personal license key. When setting up OmniCraft ERP on a new computer, enter your key in Program Settings: all previously acquired extensions unlock automatically.

Can an unused module be hidden from the sidebar menu? ​

Yes. You can toggle sidebar menu visibility in workspace settings to keep your interface clean and focused without deleting underlying module database tables.
